# CO-CRAFT Span-Level Method

## 1. Goal

CO-CRAFT-Span generalizes CO-CRAFT-Token from individual tokens to semantic spans. It keeps the same CRAFT outer objective:

\[
\widetilde S_c - f^*(\widetilde S_r),
\]

but computes importance weights for spans rather than isolated tokens.

The main idea is:

\[
\boxed{
\text{outer sequence-level asymmetry: } f^*
}
\]

\[
\boxed{
\text{inner span-level importance: } f'
}
\]

Token-level CO-CRAFT is a special case of span-level CO-CRAFT where each span contains exactly one token.

---

## 2. Why Span-Level?

Token-level weighting can be noisy when chosen and rejected responses differ in wording, length, or structure. LLM responses often differ by:

- phrases,
- clauses,
- sentences,
- reasoning steps,
- semantic units.

Span-level weighting smooths token-level noise and gives a more semantic importance signal.

Example:

```text
Chosen:
The correct answer is 42 because 6 times 7 equals 42.

Rejected:
I am not sure, but maybe the result is 36.
```

A token-position comparison may be noisy. A span-level comparison can focus on meaningful units such as:

```text
"the correct answer is 42"
"the result is 36"
"because 6 times 7 equals 42"
```

---

## 3. Self-Play Setting

For each prompt \(x\), we have:

\[
y=[y_1,\ldots,y_T]
\]

as the chosen response, and:

\[
y'=[y'_1,\ldots,y'_{T'}]
\]

as the rejected response generated by:

\[
y'\sim \pi_{\theta_k}(\cdot\mid x).
\]

Here:

- \(\pi_{\theta_k}\): frozen self-play checkpoint,
- \(\pi_\theta\): model being optimized,
- \(y\): chosen response,
- \(y'\): self-generated rejected response.

---

## 4. Span Segmentation

Segment the chosen response into \(M\) spans:

\[
y=[s_1^c,\ldots,s_M^c],
\]

where:

\[
s_m^c = y_{l_m^c:r_m^c}.
\]

Segment the rejected response into \(N\) spans:

\[
y'=[s_1^r,\ldots,s_N^r],
\]

where:

\[
s_n^r = y'_{l_n^r:r_n^r}.
\]

Possible span definitions:

1. **Fixed token blocks:** every \(K\) tokens.
2. **Word spans:** whitespace-based spans.
3. **Clause spans:** split by punctuation or discourse markers.
4. **Sentence spans:** split by sentence boundaries.
5. **Reasoning-step spans:** split by `Step 1`, `Step 2`, `Therefore`, etc.

Recommended practical setup:

```text
General instruction data: clause or sentence spans
Reasoning data: reasoning-step spans
Fast baseline: fixed 8-token spans
```

---

## 5. Span Alignment

Span-level weighting needs a mapping between chosen spans and rejected spans.

Let:

\[
A(m)
\]

map chosen span \(m\) to a rejected span or rejected prefix index.

Let:

\[
B(n)
\]

map rejected span \(n\) to a chosen span or chosen prefix index.

### 5.1 Same-Index Alignment

\[
A(m)=m,
\qquad
B(n)=n.
\]

Use when \(M\approx N\) and response structures are similar.

### 5.2 Length-Normalized Alignment

\[
A(m)=
\left\lfloor
m\cdot\frac{N}{M}
\right\rfloor,
\qquad
B(n)=
\left\lfloor
n\cdot\frac{M}{N}
\right\rfloor.
\]

Recommended default because it is simple and robust when the number of spans differs.

### 5.3 Similarity-Based Alignment

Align spans using lexical similarity, sentence embeddings, hidden-state similarity, or dynamic programming.

This is more robust but more expensive. It is best used as an ablation or extension.

## 6. Span-Level Log-Ratio

For a chosen span:

\[
s_m^c = y_{l_m^c:r_m^c},
\]

the own-prefix log-likelihood is:

\[
\log P_m^c(s_m^c)
=
\sum_{i=l_m^c}^{r_m^c}
\log
\pi_{\theta_k}
(
y_i
\mid
x,y_{<i}
).
\]

The competing-prefix log-likelihood evaluates the same chosen span under the aligned rejected prefix:

\[
\log Q_m^c(s_m^c)
=
\sum_{i=l_m^c}^{r_m^c}
\log
\pi_{\theta_k}
(
y_i
\mid
x,
y'_{<l_{A(m)}^r},
y_{l_m^c:i-1}
).
\]

The chosen span log-ratio is:

\[
\Delta_m^c
=
\frac{1}{|s_m^c|^\alpha}
\left[
\log P_m^c(s_m^c)
-
\log Q_m^c(s_m^c)
\right].
\]

For a rejected span:

\[
s_n^r=y'_{l_n^r:r_n^r},
\]

define:

\[
\Delta_n^r
=
\frac{1}{|s_n^r|^\alpha}
\left[
\log P_n^r(s_n^r)
-
\log Q_n^r(s_n^r)
\right].
\]

Recommended:

\[
\alpha=1.
\]

This makes the span score an average per-token log-ratio, preventing long spans from automatically receiving larger scores.

---

## 7. Efficient Span Approximation

Exact competing-prefix span likelihood may require additional forward passes. A cheaper implementation is:

1. compute token-level cross-prefix log-ratios;
2. average token log-ratios within each span;
3. apply the span-level \(f'\)-critic;
4. broadcast span weights to tokens.

For a chosen span:

\[
\Delta_m^c
=
\frac{1}{|s_m^c|}
\sum_{t\in s_m^c}
\Delta_t^c.
\]

For a rejected span:

\[
\Delta_n^r
=
\frac{1}{|s_n^r|}
\sum_{j\in s_n^r}
\Delta_j^r.
\]

This is the recommended first implementation.

---

## 8. Span-Level Centered \(f\)-Critic

The span-level centered critic is:

\[
a_m^c
=
a_f(\Delta_m^c)
=
f'(e^{\Delta_m^c})-f'(1).
\]

For rejected spans:

\[
a_n^r
=
a_f(\Delta_n^r)
=
f'(e^{\Delta_n^r})-f'(1).
\]

This is the same CO-CRAFT principle as token-level weighting, but applied to span log-ratios.

---

## 9. Span Weights

The positive span weights are:

\[
G_m^c
=
\mathrm{NormClip}
\left(
\exp
\left[
\mu\cdot
\mathrm{clip}(a_m^c,L,U)
\right]
\right),
\]

\[
G_n^r
=
\mathrm{NormClip}
\left(
\exp
\left[
\mu\cdot
\mathrm{clip}(a_n^r,L,U)
\right]
\right).
\]

For spans, \(\mathrm{NormClip}\) normalizes across spans:

\[
\mathrm{NormClip}(\tilde G_m)
=
\mathrm{clip}
\left(
\frac{
\tilde G_m
}{
\frac{1}{M}\sum_{q=1}^{M}\tilde G_q+\epsilon
},
G_{\min},
G_{\max}
\right).
\]

Recommended defaults:

\[
\mu\in\{0.5,1.0\},
\qquad
L=-2,
\qquad
U=2,
\]

\[
G_{\min}=0.25,
\qquad
G_{\max}=4.0.
\]

All weights should be computed under `no_grad` and detached.

---

## 10. Broadcast Span Weights to Tokens

The easiest implementation is to broadcast each span weight to all tokens inside that span.

If token \(y_t\) belongs to chosen span \(s_m^c\), then:

\[
g_t^c=G_m^c.
\]

If token \(y'_j\) belongs to rejected span \(s_n^r\), then:

\[
g_j^r=G_n^r.
\]

Then the weighted scores remain token-sum scores:

\[
\widetilde S_c
=
\sum_{t=1}^{T}
g_t^c
\beta
\log
\frac{
\pi_\theta(y_t\mid x,y_{<t})
}{
\pi_{\theta_k}(y_t\mid x,y_{<t})
},
\]

\[
\widetilde S_r
=
\sum_{j=1}^{T'}
g_j^r
\beta
\log
\frac{
\pi_\theta(y'_j\mid x,y'_{<j})
}{
\pi_{\theta_k}(y'_j\mid x,y'_{<j})
}.
\]

The final objective is:

\[
\mathcal L_{\mathrm{CO\text{-}CRAFT\text{-}Span}}
=
\mathbb E
\left[
\ell
\left(
\widetilde S_c
-
f^*(\widetilde S_r)
-
\widetilde v
\right)
\right].
\]

---

## 11. Direct Span-Score Alternative

Instead of broadcasting, one can compute span scores directly:

\[
\widetilde S_c
=
\sum_{m=1}^{M}
G_m^c
\beta
\log
\frac{
\pi_\theta(s_m^c\mid x,y_{<l_m^c})
}{
\pi_{\theta_k}(s_m^c\mid x,y_{<l_m^c})
}.
\]

Since autoregressive span likelihood is a sum of token likelihoods:

\[
\log
\frac{
\pi_\theta(s_m^c\mid x,y_{<l_m^c})
}{
\pi_{\theta_k}(s_m^c\mid x,y_{<l_m^c})
}
=
\sum_{i=l_m^c}^{r_m^c}
\log
\frac{
\pi_\theta(y_i\mid x,y_{<i})
}{
\pi_{\theta_k}(y_i\mid x,y_{<i})
}.
\]

This is mathematically clean but requires more bookkeeping.

Recommended implementation:

```text
compute span weights
broadcast them to token losses
```

## 12. Algorithm

```text
Input:
    SFT data D = {(x_i, y_i)}
    frozen self-play model pi_theta_k
    trainable model pi_theta
    divergence f, conjugate f*, derivative f'
    beta, mu, L, U, G_min, G_max
    span segmentation strategy
    span alignment strategy

For each self-play pair (x, y, y'):

    1. Segment chosen response y:
           s_1^c, ..., s_M^c

    2. Segment rejected response y':
           s_1^r, ..., s_N^r

    3. Build span alignment maps:
           A(m): chosen span -> rejected span/prefix
           B(n): rejected span -> chosen span/prefix

    4. Compute token-level cross-prefix deltas
       or exact span competing-prefix likelihoods.

    5. For each chosen span s_m^c:
           Delta_m^c =
               average token Delta inside the span
               OR exact length-normalized span log-ratio

           a_m^c =
               f'(exp(Delta_m^c)) - f'(1)

           raw_G_m^c =
               exp(mu * clamp(a_m^c, L, U))

    6. Normalize and clip chosen span weights.

    7. Repeat steps 5-6 for rejected spans.

    8. Broadcast span weights to token weights:
           if token y_t belongs to s_m^c:
               g_t^c = G_m^c

           if token y'_j belongs to s_n^r:
               g_j^r = G_n^r

    9. Detach all weights.

    10. Compute weighted scores:
           S_c_tilde, S_r_tilde

    11. Optimize:
           ell(S_c_tilde - f*(S_r_tilde) - v_tilde)
```

## 13. Efficient Implementation Pseudocode

```python
def compute_span_weights_from_token_delta(
    chosen_delta,
    rejected_delta,
    chosen_spans,
    rejected_spans,
    f_critic_fn,
    mu=0.5,
    L=-2.0,
    U=2.0,
    g_min=0.25,
    g_max=4.0,
    eps=1e-8,
):
    chosen_token_weights = torch.ones_like(chosen_delta)
    rejected_token_weights = torch.ones_like(rejected_delta)

    for b in range(chosen_delta.size(0)):
        raw_chosen = []

        for (l, r) in chosen_spans[b]:
            span_delta = chosen_delta[b, l:r].mean()
            span_score = f_critic_fn(span_delta)
            raw_weight = torch.exp(mu * torch.clamp(span_score, L, U))
            raw_chosen.append(raw_weight)

        raw_chosen = torch.stack(raw_chosen)
        span_weights = raw_chosen / (raw_chosen.mean() + eps)
        span_weights = torch.clamp(span_weights, g_min, g_max)

        for m, (l, r) in enumerate(chosen_spans[b]):
            chosen_token_weights[b, l:r] = span_weights[m]

        raw_rejected = []

        for (l, r) in rejected_spans[b]:
            span_delta = rejected_delta[b, l:r].mean()
            span_score = f_critic_fn(span_delta)
            raw_weight = torch.exp(mu * torch.clamp(span_score, L, U))
            raw_rejected.append(raw_weight)

        raw_rejected = torch.stack(raw_rejected)
        span_weights = raw_rejected / (raw_rejected.mean() + eps)
        span_weights = torch.clamp(span_weights, g_min, g_max)

        for n, (l, r) in enumerate(rejected_spans[b]):
            rejected_token_weights[b, l:r] = span_weights[n]

    return chosen_token_weights.detach(), rejected_token_weights.detach()
```

## 14. Implementation Checklist

- Segment only response tokens, not prompt tokens.
- Avoid spans that are too long.
- Recommended span length: 4--32 tokens.
- Use length-normalized log-ratio.
- Use length-normalized span alignment as default.
- Compute weights with frozen \(\pi_{\theta_k}\).
- Detach all weights.
- Normalize span weights to mean one.
- Clip span weights into a safe range.
- Broadcast span weights to token losses.
- Use JS as the default divergence.

## 16. Paper-Ready Paragraph

```latex
\paragraph{Span-level conjugate-originated weighting.}
Although token-level weighting provides fine-grained supervision, self-play responses often differ at the phrase, clause, or reasoning-step level rather than at isolated token positions. We therefore generalize the conjugate-originated critic from tokens to spans. Let $s_m^c=y_{l_m:r_m}$ denote a chosen span. We compute its length-normalized cross-prefix log-ratio as
\[
\Delta_m^c =
\frac{1}{|s_m^c|^\alpha}
\left[
\log P_m^c(s_m^c)-\log Q_m^c(s_m^c)
\right],
\]
where $P_m^c$ is the likelihood of the span under the chosen prefix and $Q_m^c$ is the likelihood of the same span under the aligned rejected prefix. The span score is then transformed using the centered optimal $f$-critic,
\[
a_f(\Delta_m^c)=f'(e^{\Delta_m^c})-f'(1),
\]
and converted into a positive span weight by exponentiation, normalization, and clipping. The resulting span weight is broadcast to all tokens inside the span when constructing the weighted chosen and rejected sequence scores. Token-level CRAFT is recovered as a special case when each span contains exactly one token.
```

## 17. Recommended Paper Positioning

The cleanest way to position span-level CRAFT is:

```text
CRAFT uses f* for sequence-level rejected-score transformation.
CRAFT uses f' for span-level importance estimation.
Token-level CRAFT is a special case of span-level CRAFT.
```

This gives the final method a strong identity:

\[
\boxed{
\text{CRAFT couples sequence-level asymmetry and span-level importance through one } f\text{-divergence principle.}
}
\]
